# 经纶

月度回合制国家治理沙盘。当前版本为 `0.10.0-gameplay`，已进入 gameplay 阶段，首先提供轨道观测视角的游戏入口与 Debug 模式；国家、人口、经济、改革与战争尚未接入。

## 当前技术方案

- **Rust 内核：** 独立的连续环境底图、Voronoi 与 Lloyd 松弛、水汽输送、雨影、逐月气候、积雪融雪、土壤蓄水、汇流河网与基本湖泊、季节农业条件、十类资源潜力与分区汇总。
- **Rust 后端：** Axum HTTP API，耗时生成在后台计算任务执行，并限制并发数量。
- **TypeScript 前端：** Vite、React、Motion、SVG 底图与按需加载的 PixiJS 河网叠加，只处理界面、地图展示、缩放与选择，不执行世界生成。
- **i18n：** 文案、数值格式、地形与资源标签、API 错误统一经过语言接口；目前只有 `zh-CN`，没有英文语言包或切换按钮。
- **前后端分离：** 当前不使用 WebAssembly。模拟内核不依赖 Axum，可在未来单独评估 WASM 适配。

## 启动

需要 Node.js 22.12 及以上版本、支持 Rust 2024 edition 的 Rust 工具链。本次验证环境为 Node 22.18.0、Rust/Cargo 1.96.1。

```sh
npm install
npm run dev
```

- 页面：<http://127.0.0.1:5173>
- 后端：<http://127.0.0.1:3001>
- 首次运行会编译 Rust 后端；启动脚本等后端就绪后再启动页面，避免编译期间请求失败。
- `Ctrl+C` 停止前后端。
- 启动脚本会查找 `~/.cargo/bin/cargo`，无需修改全局 PATH。项目默认使用 `.cache/cargo` 缓存依赖；已设置 `CARGO_HOME` 时保留该设置。

也可以分别启动：

```sh
npm run dev:server
npm run dev:web
```

## 版本阶段

`0.9.2-geo` 及以前的项目版本统一使用 `-geo` 后缀；从 `0.10.0-gameplay` 起使用 `-gameplay`，数字连续递增。历史 Git 提交不重写。地理数据契约独立保留为 `0.9.0-geo`，不随界面版本递增；本轮只调整其阶段标识，未修改地理算法。自然指纹包含生成器版本，因此重命名后指纹也会变化。

## 游戏入口

默认进入创世参数配置，页面打开时不自动生成地图。点击「生成这片世界」成功后，左栏缩为「是否确认地图？」及「重新生成」「确认」两个按钮，当前地图固定为预览。点击「重新生成」只返回参数界面，原预览保留；编辑参数不会改变地图，需再次点击生成才更新。生成期间参数暂不可编辑，失败后可修改或重试。

点击「确认」后使用同一份地图进入首回合「新纪元1年1月」，左栏显示当前回合，顶栏显示日期。进入回合后不再提供创世参数或重新生成入口，Debug 切换也不会替换地图、重置开局或改变正式日期。右下角圆形播放按钮为「下一回合」，只在悬停或键盘聚焦时显示提示；点击推进一个月，十二月后进入下一年一月。按钮随右栏展开向左让位，保持可点击。尚未实现经济等月度结算或存档恢复；刷新会重新进入创世配置。

未生成地图时显示 SVG 星环标志及轨道背景。进入回合后默认隐藏图例和右栏，点击地块才显示自然地形图例并打开右栏。所有地块默认处于信息迷雾：普通模式的悬停与右栏只显示地块编号，不挂载完整档案或候选地比较；地图仍可观察自然外观并平移缩放。当前没有已勘探地块，也不自动选中禀赋较好的地区。

右上角「游戏菜单」可以切换外观或启用「Debug 模式」。开启后显示地块档案、候选地比较、十个图层、逐月播放、快速定位与完整 JSON 导出；创世参数界面仍保留 Debug 世界概览。退出时切回自然地形并停止播放；回合内保留所选地块，右栏恢复仅编号的迷雾视图。刷新页面默认关闭 Debug，不保存开启状态。窄屏下创世参数可通过左侧标签展开。

这一步只划分玩家展示与调试工具，探索、勘探、登陆选址和月度结算规则尚未接入。模式切换复用已生成的世界，不重新请求地图。

## Debug 地图操作

1. 输入种子，选择 100—2,000 个地块、0—3 次松弛与 20%—80% 目标陆域面积（含内陆湖泊）。
2. 点击「生成这片世界」。默认 500 块、2 次松弛、约 45% 陆域；矩形平面，不左右环绕。
3. 十个图层均按地块汇总值整块填色，一块一种底色；主要河流可单独开启，默认关闭。气温与降水可选择全年或某个月份，切换月份不重新生成世界或推进游戏时间。
4. 点击地块，或使用编号选择器查看详情；邻接按钮可以跳转到相邻地区。`⌘/Ctrl+K` 打开快速定位，支持地块编号、地形和图层搜索。
5. 滚轮缩放、拖动平移；右侧工具可放大、缩小和适应画布，小地图可快速移动视点。按 `?` 查看快捷键；空格播放逐月气候，按钮获得焦点时保留原生空格操作。
6. 导出地图获得完整 JSON，包含种子、参数、生成器版本、多边形与拓扑。设置本地保存，世界本身由 Rust 根据种子重新生成。
7. 桌面底部图层栏随可用空间换行；窄屏默认收起两侧面板，同一时间只展开一侧，底部操作始终保留。
8. 游戏菜单中的「外观主题」可选择跟随系统、浅色或深色。默认跟随系统，手动选择在本机浏览器保存；切换仅更新配色，保留地图、选区、视野、图层与季节播放状态。浅色版使用独立的明亮地形和专题色板，并同步小地图、玻璃面板、图例、图表和弹窗，保留原有动效。

生成器 0.9.0-geo 保留独立的 256 × 160 环境采样用于 Rust 计算；同种子和陆域比例下，改变地块数量不会重新生成自然环境。页面统一使用 Voronoi 地块填色，显示海岸线沿地块边界绘制。改变地块数量会改变地图的概括程度；详情仍保留内部海陆、湖泊与潜在可耕面积比例。湖泊不以细碎色斑叠加，只有成为地块主导地形时才整块显示。

当前详情将地貌、冷热、干湿、植被、土壤质量、雨养农业适宜度与灌溉改善潜力分别展示。高海拔不再自动等于陡峭；靠河的干旱区可以具有开发机会，但尚未建设灌溉或产生农业产量。

第二轮地理深化加入南北半球相反的季节、沿海与内陆温差、降雪暂存与融化、跨月土壤蓄水和水分预算。农业指数使用暖季持续时间与同期供水，苔原和全年冻结地表分别表示。地块档案新增全年逐月气候表与生长月数。模型参数、单位和简化边界见 [季节气候说明](docs/SEASONAL_CLIMATE.md)。

### 封闭盆地与季节湖泊

第三轮补上内流湖、季节溢流湖、常年溢流湖与干盆地。十二个月的本地产流沿无循环网络汇集，湖盆按实际可用水蒸发，超过容量才溢出；蓄水增减进入逐月和年度账本。地块档案新增「流域与湖泊」，展示内流区占陆域比例、关联湖泊及其逐月高程、蓄水比例和溢流状态。地图仍一块一色，湖面变化不逐月重画地块。

河段的月度汇流数据已由 Rust 生成；SVG/Pixi 线宽与透明度随月份变化，实际断流河段隐藏。初始蓄水是按年平均条件估算的参考储量，不是额外降水；也不直接等于可取用淡水。当前采用气候到湖泊的单向耦合，湖面尚不反过来重算当地土壤和降水。具体模型与后续清单见 [湖盆与水量说明](docs/LAKE_BASINS.md)。

### PixiJS 基础接入

已固定接入 `pixi.js@8.22.0`。开启「显示主要河流」时才加载 WebGL 模块，使用 Rust 返回的真实河网；普通地图仍使用 SVG，保留一块一色与现有地块交互。两种绘制共享相机、视口、像素比与选择状态，河流按陆地为主的地块轮廓裁剪。显示层省略细短的孤立水系与支流，保留主干和汇流连接；统计及导出仍使用完整河网。

河网为静态、按需重绘，没有持续运行的 ticker。关闭河网、重新生成世界或销毁地图时释放 GPU 资源；WebGL 不可用、模块加载失败或上下文丢失时自动使用 SVG 河流线。当前尚无物流、能源、人口数据，也未实现相应粒子、飞线或夜间灯光。接入边界与验收见 [渲染规划](docs/RENDERING_PLAN.md)。

## 检查与构建

```sh
npm test                  # 前端相机/生命周期测试 + Rust 内核与 HTTP 接口测试
npm run test:web          # 只检查前端相机、异步接入与降级生命周期
npm run test:rust         # 只检查 Rust 内核与 HTTP 接口
npm run build             # TS 类型检查与前端生产构建，输出 dist/
npm run build:server      # Rust 后端 release 构建
npm run fmt               # Rust 格式化
```

生产环境由 Nginx 直接提供 `dist/` 静态文件，并将 `/api/` 反向代理到 release 后端：

```sh
./deploy/deploy-frontend.sh       # 构建前端、安装并重载 Nginx 配置
./deploy/run-release-backend.sh   # 编译并前台运行 release 后端，适合放入 screen
```

前端脚本使用 ACL 仅授予 `www-data` 读取项目内 `dist/` 的权限；Ubuntu 首次使用前如缺少命令，请运行 `sudo apt install acl`。

`npm run dev` 和 `npm run dev:server` 始终使用 Rust debug 构建；生产后端由上述独立脚本启动。

开发服务由 Vite 代理 `/api` 到 Rust。`npm run preview` 可预览已构建前端，仍需启动 Rust 后端。

开发服务运行时，可访问 <http://127.0.0.1:5173/tests/rendering.html>，手动验证真实 WebGL 上下文丢失、SVG 降级、重新启用和销毁重建。该验收页不是生产构建入口。

## 接口

`GET /api/health`

### 生成地图

`POST /api/maps/generate`

```json
{
  "seed": "经纶·山河初定",
  "cell_count": 500,
  "relaxations": 2,
  "land_ratio": 0.45
}
```

返回 `{ "map": { ... }, "meta": { "generation_ms": 0.0 } }`。当前 `generator_version` 为 `0.9.0-geo`。地块包含逐月气候、内流陆域占比与关联湖泊；`environment.basins` 包含湖盆类型和十二个月的水量、蓄水、高程；河段包含同一断面上的年度与月度汇流量。地块增加土层、矿藏份额与建设条件，`environment` 增加尺度、地质区、矿床和泥沙账本；边增加天然廊道评估。地块保留地下水逐月档案和 `water_source_ids`；`environment.water_sources` 提供唯一流域的逐月共享取水上限和天然水质；河段增加月度强度。水量账本包含雪、土壤、地下水、湖泊储量变化及逐月盐分收支。相同生成器版本、种子与参数生成相同 `map`；耗时为独立的非确定性元数据。跨版本不保证重现旧版气候、河网与农业结果。

错误返回 `{ "error": { "code": "error.cell_count", "params": { "min": 100, "max": 2000 } } }`，由前端翻译。参数非法返回 422，格式错误返回 400，计算并发已满返回 429。

## 地理原型的边界

资源保留 0—100 的相对潜力指数，矿床另有有限地质估计量；两者都不代表已探明储量；没有矿山、产业、国家或产量。气候为逐月长期平均常态，已加入二维水汽输送、简化季风与季节雨带，已加入静态海盆环流与逐月海温反馈，没有逐日天气、动态海洋或完整大气环流求解；湖泊使用封闭盆地、月度蓄水与蒸发桶模型，已加入湖底渗漏、地下水基流、天然矿化度与流域共享规划上限，尚无实际取水、工业污染、逐日洪水或水动力。矿产已由区域地质背景与有限矿床估计量形成，包含品位、埋深和开采难度，尚无勘探、矿山或库存消耗。

农业与灌溉只表示自然适宜度和改善机会。水量账本使用等面积采样的模型单位，可通过 `environment.scale` 换算为按游戏尺度估计的立方米；页面水源使用百万立方米，河流线不表示实测流速。地块邻接只代表共享边界，不自动创建道路、航线、电网或通行权。详见 [当前算法与单位](docs/MAP.md)与[地下水、水质和取水边界](docs/WATER_RESOURCES.md)。

参考实现文档：[Voronoice](https://docs.rs/voronoice/0.2.0/voronoice/)、[Simplex](https://docs.rs/noise/0.9.0/noise/struct.Simplex.html)、[Axum](https://docs.rs/axum/latest/axum/)、[Vite](https://vite.dev/guide/)。

0.8.0-geo 在逐月二维水汽与季风代理基础上，校准纬度温度、海陆温差和辐射相关蒸散需求，并用同一静态构造骨架关联山系、高原、盆地与岩性。矿床仍是有限估计量，水盐与泥沙账本继续守恒；本轮没有动态板块或洋流。地图仍一块一色，1—9、0 切换图层，0 查看建设，Home 适应画布。机制、温度锚点、多种子审计和限制见 [温度与构造说明](docs/THERMAL_TECTONIC.md)；0.7.0-geo 的降水模型留档见 [气候校准说明](docs/CLIMATE_CALIBRATION.md)。

0.9.0-geo 完成自然地理阶段收尾：静态海盆环流搬运热量，逐月海表温度影响水汽和沿海气温；温度图层展示海温，档案提供流向、流强和逐月偏差。补齐陆／海／湖面积、陆域海拔范围，修正纯海域汇总与沿海高程显示，加强自然指纹。参数、审计、性能与后续玩法边界见 [海温、洋流与地理收尾](docs/OCEAN_GEO_FINISH.md)。
