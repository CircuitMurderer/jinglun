# 湖盆与季节水量（0.4.0 引入，当前 0.5.0）

> 以下记录第三轮湖盆基础。第四轮增加地下水、湖底渗漏、天然矿化度和共享规划水源；增量模型与当前账本以 [WATER_RESOURCES.md](WATER_RESOURCES.md) 为准。

本轮落实地理清单中的封闭盆地、内流／蒸发出口、湖泊蓄水与逐月河道来水。全部计算在 Rust；月份仍表示气候常态中的参考月份，不推进游戏回合。

## 湖盆如何形成

Priority-flood 提供溢流面与无循环排水顺序，原始地形不被改写。保留至少四个环境采样、且最大深度至少十二米的凹地；微小噪声凹坑继续按溢流面排水。大湖盆内部收束到最低排水顺序的溢流点，出流再接入下游，因此多级湖盆仍按有向无环顺序计算。当前只处理正高程陆域中的湖盆；沿用负高程为海域的约定，尚不表达低于海平面的内陆洼地。

封闭盆地并不一定有永久水面；没有足够来水时可以是干盆。闭流区域的水可以通过蒸发或地下渗漏离开，而不经过海洋出口。本轮只计算其中的蓄水与额外蒸发，0.5.0 已加入湖底渗漏，见第四轮说明。[USGS：封闭与非贡献排水区](https://water.usgs.gov/themes/hydrofabric/drainage-area/)

## 参考储量与逐月过程

1. 用湖盆底部高程与溢流高程建立蓄水容量：水深由米转为毫米，再对等面积采样求和。它是模型体积，尚未标定为立方米。
2. 根据按年平均路由得到的来水与蒸发需求估计初始参考湖面。该储量显式导出，不记为额外降水，也不假装模拟了填满深湖需要的历史年份。
3. 各样本十二个月的本地产流分别沿排水网络汇流，湖盆只能蒸发实际可用水；剩余水先蓄存，超过溢流容量后才送往下游。
4. 本地陆地模型已经计入蒸散，因此湖面只追加尚未满足的潜在蒸散需求，避免同一份需求重复收费。直接降水已经进入陆地水量桶，不再对湖面重复添加降水。
5. 一米的岸带代理允许单个采样部分湿润，避免平底湖盆瞬间从无水跳到全湖蒸发。年均湿润比例达到一半的采样计入显示水面；小于采样尺度的水体可能只保留在盆地数据中。

这是一种守恒的、单向耦合的湖盆桶模型。它尚不针对淹没地表重新求解土壤蓄水、开放水面能量、冻结湖面或局地气候，也没有水动力；0.5.0 已增加湖底渗漏和天然矿化度，仍不是完整地质渗流或污染模型。它的目的是建立可解释的水源与水量约束，不能直接把蓄水比例视为可灌溉或可饮用淡水。

## 分类与账本

- `dry`：参考年无有效蓄水的干盆。
- `closed`：参考年蓄水但全年没有地表溢流的内流湖。
- `seasonal`：部分月份发生溢流。
- `overflow`：十二个月均发生溢流。

内流区域终止地表排水连接，不再为了让算法贯通而强迫入海。每月独立满足：

```text
地表产流 + 地下水基流 = 湖泊额外蒸发 + 湖底渗漏 + 入海流出 + 地图边界流出 + 湖泊净储量变化
湖泊来水 = 湖泊额外蒸发 + 湖底渗漏 + 湖泊溢流 + 湖泊净储量变化
```

储量变化允许为负，表示消耗已有储水。年度账本为十二个月之和，雪与土壤净储量变化仍保留在上游陆地账本。湖泊年内变动与入流相联系是常见水量关系；具体模型参数是游戏简化。[USGS：终端湖与来水变化](https://nevada.usgs.gov/walker/)

## 接口与显示

- `environment.basins`：所有保留湖盆的类型、容量、初始参考储量，以及十二个月的来水、蒸发、溢流、储量变化、月末储量和湖面高程。盆地 `id` 是此列表中的编号。
- `environment.lakes`：达到显示阈值的年均水面及对应 `basin_id`；湖泊编号可能与湖盆编号不同，因为干盆和小水体不生成显示湖泊。
- 河段 `annual_flow` 与 `monthly_flow`：同一断面上的相对模型水量，十二个月之和等于年度水量；不是实测流速。河段 `basin_id` 延续原契约，表示最终出口的环境采样编号，不等于湖盆列表编号。
- `cell.endorheic_land_fraction`：地块内部陆域中流向无溢流盆地的比例；分母不含海洋。
- `cell.lake_ids`：与地块年均水面相交的显示湖泊编号。

地图继续一块一色，不叠加细碎水面，也不按月份重画地块。档案展示湖泊类型、月度高程、相对溢流容量的蓄水比例和溢流状态；温度／降水的月份选择也会更新湖泊读数。0.5.0 的河流线已根据月份采用统一尺度的相对线宽与透明度，真实断流河段隐藏。
