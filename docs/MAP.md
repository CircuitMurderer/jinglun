# 地图原型：实现约定（生成器 0.9.0-geo）

> 已完成连续地理与第二轮季节气候、水分细化。完整方向见 [地理方案](GEOGRAPHY_PLAN.md)，季节模型见 [季节气候说明](SEASONAL_CLIMATE.md)；SVG 底图与 PixiJS 河网接入见 [渲染规划](RENDERING_PLAN.md)。

## Gameplay 入口与 Debug 模式（0.10.1-gameplay）

普通入口提供创世参数、SVG 星空与星环背景及生成后的自然地形图与基本相机操作。进入回合后默认隐藏图例及右栏，点击地块才展示图例与右栏，收起右栏时同步隐藏图例，图例和指南针避让侧栏标签；所有地块默认未勘探，普通悬停及右栏只显示编号。原世界概览、档案、候选地比较、专题图层、月度读数、定位搜索和完整导出统一放到右上角游戏菜单的 Debug 模式，相关快捷键也只在 Debug 生效。普通模式不使用水源／农业条件自动选择候选地。退出 Debug 关闭完整分析并恢复自然地形；回合内保留所选地块，右栏恢复仅编号，刷新默认关闭 Debug。

应用版本为 `0.10.1-gameplay`；地理生成器阶段标识为 `0.9.0-geo`。算法保持不变，但生成器版本参与自然指纹，阶段标识变化会使指纹变化。入口现按「参数配置 → 地图确认 → 首回合」推进，首回合为新纪元1年1月。确认后复用当前地图，普通模式和 Debug 均无再次生成入口；右下角圆形播放按钮推进一个月，十二月跨年，随右栏展开向左移动。地图外缘使用24px渐隐遮罩与深海色背景过渡；遮罩通过共享相机投影定位，同时覆盖 SVG、GPU 河流、选区与纬度标签。地理月份浏览与正式回合日期独立。此轮没有实现正式勘探、登陆或经济等月度结算。

## 运行与数据边界

所有自然环境、Voronoi、气候、汇流、湖泊、指标和分区汇总在 Rust 执行。TS 根据地块汇总值选择颜色、绘制 Voronoi 多边形与可选河流线，管理选择、相机、图层、图例与中文详情。SVG 保留底图与选择；开启河流线时按需加载 PixiJS 8.22.0，使用同一河网数据与共享相机进行 WebGL 静态叠加，失败时退回 SVG。没有 deck.gl 或 WASM 依赖。

`crates/world/src/environment.rs` 生成与汇总自然环境，`tectonics.rs` 提供地形与岩性共享的静态构造骨架，`thermal.rs` 提供温度与辐射蒸散基准，`ocean.rs` 提供海盆环流、海温和沿海反馈，`atmosphere.rs` 处理逐月二维水汽与降水，`seasonal.rs` 处理温度、潜在蒸散和陆地水分，`lakes.rs` 处理湖盆蓄水和盐分，`water.rs` 处理地下水与共享水源，`hydrology.rs` 处理汇水与水量账本，`lib.rs` 处理配置、Voronoi 与世界组装。HTTP 仍由独立服务封装，计算在 `spawn_blocking` 中执行。

## 两套空间结构

- **自然环境：** 固定 256 × 160 等面积模型采样，世界范围 1,600 × 1,000 地图单位。自然海岸、山川、气候、河网不依赖地块数量与 Lloyd 次数。
- **治理分区：** 100—2,000 个 Voronoi 多边形，完整铺满矩形；Lloyd 采用面积质心。分区允许同时包含海洋、陆地和湖泊。
- **汇总：** 环境采样中心按最近种子归属到 Voronoi 分区，统计面积比例和陆地属性。面积极小、没有采样中心的地块使用质心附近的单点回退。

地块几何面积仍精确由多边形计算，内部面积组成是固定分辨率采样近似。调整分区后地区指标可能变化，但 `environment` 整体保持一致。自然底图指纹用于辅助识别，仍需结合生成器版本。

## 生成步骤

1. 从独立种子域形成静态构造分区和边界；多尺度 Simplex 保留大陆轮廓，共同构造信号及噪声细节生成山系、高原、盆地与岩性。详见 [温度与构造](THERMAL_TECTONIC.md)。
2. 在自然采样上确定海平面，陆域比例误差控制在约两个环境采样以内，独立于 Voronoi 数量。陆域口径包含内陆湖泊。
3. 由局部邻域相对起伏计算平坦度；结合海拔区分低地、高原、丘陵和山地。该平坦度是游戏指数，0.6.0-geo 已按每地图单位 10 公里的游戏约定标定距离，但平坦度仍不是实测坡度角。
4. 使用 −75° 至 +75° 的平滑纬度温度曲线、有限大陆性偏移和每公里 6℃ 的高度修正；低地纯海洋性背景在 30°、45° 约为 20℃、12℃。这是合成宜居世界基准，不是实测气候或完整球面模拟。
5. 在固定网格逐月计算简化风场和雨带；四组有向输送流沿横、纵两条边传播水汽，海面补充量受当月方向权重和 0.9.0-geo 海表温度控制，静态海盆环流先于大气求解。海陆热力梯度形成季风代理，上坡额外凝结；每月及全年分别核对海洋供水、降水与边界输出。详见 [气候校准](CLIMATE_CALIBRATION.md)。
6. 根据有符号纬度和固定网格距海代理，生成南北半球相反、沿海温差较小的12个月的均温。降水直接使用当月输送结果，全年是十二个月之和；没有再次按权重分配年雨量。0.8.0-geo 的潜在蒸散改用辐射与日温差代理，P/PET 分类阈值不变。0.9.0-geo 在陆地月温叠加衰减的洋流偏差，再计算蒸散。这些是气候常态，没有逐日天气或完整大气／海洋动力学。
7. 基于 Priority-Flood 思路求出溢流高度和无循环排水关系；普通坡面优先选择更陡的下坡，平坦水面用确定处理顺序解开流向。[算法背景](https://arxiv.org/abs/1511.04463)
8. 冷月降雪暂存，暖月按有限融化能力释放；液态水进入有容量的土壤水桶，分配为实际蒸散、深层补给与地表产流。年产流进入河网汇集，积雪与土壤储水变化一并记账。小凹坑用于排水计算，不直接改变原始海拔。
9. 保留有意义的封闭凹地作为湖盆：至少四个采样、最深处至少低于溢流面十二米。按年均水量估计初始参考储水，再将逐月产流经过湖盆蒸发、蓄存与溢流路由；没有来水的盆地不自动成湖。参考年无溢流的湖盆作为内流终点。详见 LAKE_BASINS.md。
10. 土壤质量由区域母质、参考侵蚀沉积后的土层、砂质、有机质与淋溶代理组成；根区容量已参与水文重算；雨养农业使用各月温度、实际／潜在蒸散比例和生长季长度。潜在可耕面积与灌溉改善潜力分别保存。按最暖月区分苔原与全年冻结地表，年均温低于零度不再直接决定永久积雪。
11. 将连续自然属性汇总到地块，并返回可翻译的成因标识。自然地理层使用主导表现，详情保留地貌、气候与植被的独立属性。

## 字段与单位

| 字段 | 定义 |
| --- | --- |
| `area`、边长与坐标 | 地图单位及其平方，原始值仍为地图单位；`environment.scale` 提供游戏公里、面积和水量换算 |
| `elevation_m` | 地块全区海拔平均值，米；海底为负；陆地海拔图改用下方陆域均值 |
| `geography` | 地区纬度、总面积及陆／湖／海面积（平方公里）、陆域采样高程范围（米，含湖床） |
| `ocean` | 含海洋采样时的逐月海温、相对无洋流基准的偏差和向东／向北矢量及相对流强；纯陆地为 null |
| `temperature_c`、`rainfall_mm` | 区内陆域平均近似；纯海域按全部海洋采样平均，温度使用海表温度代理 |
| `climate.months[0..11]` | 一月至12个月的气候常态：均温℃；降水、降雪、融雪、蒸散、产流、补给与月末土壤储水均为毫米水当量。不是雪厚或河流流量 |
| `climate.growing_months`、`rainfed_months` | 温度适生月份与同时满足简化水分条件的月份，按区内陆地平均，可为小数；不是某一种作物的成熟月份 |
| `climate.continentality` | 固定自然网格距海代理形成的 0—1 大陆性，不是公里 |
| `climate.snow_storage_change_mm`、`soil_storage_change_mm` | 参考年积雪与土壤储量净变化。永久积雪累积保留在账本中，不强行化成河流 |
| `land_fraction` | 陆域占地块比例，含内陆湖泊 |
| `lake_fraction` | 湖泊占整个地块比例，不是陆域内部比例 |
| `endorheic_land_fraction` | 地块内部陆域中流向封闭盆地的比例 |
| `lake_ids` | 与地块年均水面采样相交的湖泊编号 |
| `is_land` | 陆域占比至少 50%，只表示分区主导类型 |
| `landform` | 区内陆地的主导地貌 |
| `thermal_zone`、`moisture_zone`、`vegetation` | 区内陆地各分类的主导类型，不互相代替 |
| `flatness` | 局部相对起伏推导的 0—100 指数 |
| `soil_quality` | 0—100 土壤条件；取代旧版混合意义的 `fertility` |
| `agricultural_suitability` | 0—100 雨养农业适宜度，不是产量 |
| `arable_fraction` | 在当前自然与附近水源代理条件下具有开发潜力的面积占全区比例；不代表已开垦 |
| `irrigation_potential` | 0—100 灌溉改善机会，尚未建设或批准取水 |
| `river_access` | 陆域采样中接近主河网或湖泊的比例指数，不是可无限领取的水量 |
| `resources[].potential` | 0—100 相对资源潜力，混合分区按陆域比例缩放 |
| `rivers[].flow_index` | 相对流量视觉指数，不是流速或立方米每秒 |

纯海域不赋予陆地资源。矿藏已由地质区中的连续赋存潜力形成有限矿床估计，地块份额守恒；没有完整成矿历史、已探明吨数或实际采矿。

## 水系与账本

- 河流沿自然采样排水关系流动，可以穿越治理地块；以支流汇合点、湖泊和出口分段。
- 页面的“河网分段”不是独立河流数量。边界陆地可以显式流出地图，海域出口与边界出口分开记录。
- 河水可以由湿润上游带入干旱下游；零上游来水不会凭空生成河流。
- 湖盆区分干涸、内流、季节溢流与常年溢流；基于气候常态的逐月蓄水不是完整水动力。已加入天然矿化度、湖底渗漏与地下水回补，仍无河道侵蚀、实际取水或人为污染。详见 [水资源模型](WATER_RESOURCES.md)。
- 水量账本保留等面积采样上的模型水深和；0.6.0-geo 通过尺度元数据换算为游戏估计体积，不是实测流量。浮点误差允许在严格相对容差以内。

账本满足：

```text
水汽补充 ≈ 凝结降水 + 边界水汽输出（逐月及全年）
陆域降水 ≈ 陆地蒸散 + 深层补给 + 地表径流 + 积雪储量变化 + 土壤储量变化
地表径流 + 土壤深层补给 ≈ 湖泊附加蒸发 + 入海流出 + 地图边界流出 + 湖泊净储量变化 + 地下水净储量变化
```

海域采样的水汽降水不计入陆地径流。水系几何与水量代理都来自 Rust，不靠前端装饰线伪造。

## 显示与拓扑

- 十个图层均采用整块单色填充：自然地理按主导地形，其他图层按地块汇总指标映射颜色。温度与降水可选择全年或指定月份，干湿底色仍表示长期条件，其月份控件会同步河流与水文档案。页面不叠加细网格色带，底色边界与可选地块完全一致。
- 海洋面积过半的地块统一显示深海或浅海，陆地为主的地块使用陆域主导地形；混合区的内部比例保留在详情中。自然湖泊仅在成为地块主导地形时整块着色，不额外绘制局部湖泊色斑。
- 显示海岸线使用海陆地块之间的共边；自然采样海岸和色带路径仍保留在导出数据中，当前页面不绘制。改变地块密度会改变显示海岸的概括程度，不会重新生成环境场。
- 数值映射在色标上限饱和，例如降水 2,400 毫米，原始指标不被截断。海域在温度层显示海表温度，海拔层表达全区含海底高程，其余专题层保持水域底色。
- 河流仅作为默认关闭的可选线条叠加，按地块陆域轮廓裁剪，避免越过显示海岸；其源头与路径仍来自 Rust 汇流结果。
- 河流线宽与透明度随全年／月份变化，实际断流河段隐藏；仅用于表达相对强度，缩放时保持可读性，不代表实测河宽。
- 显示层以三个环境采样间距为最小支流长度，省略网格造成的细短横杠：按完整汇流网络保留每个较长水系的主干和足够长的支流，主干上的短连接段不会单独删掉。SVG 与 WebGL 共用这一筛选；保留的路径坐标、原始水量、河网统计及 JSON 导出不变。真实的较长东西向河段仍会显示，不按方向删线。
- SVG 与 WebGL 使用相同的陆域地块裁剪、适应画布留白与平移缩放。GPU 画布不接收指针事件，中心点与选中高亮保留在最上方 SVG。高像素比绘制上限为 2 倍，像素比或布局变化后重新匹配视口；普通地图不创建 GPU 画布。
- 多边形共边邻接仍表示行政几何接触；`edges.kind` 按两端主导海陆类型粗分，不是实际海岸测量，也不是现成道路或通行权。
- 未来陆路、水路与港口应基于连续地表和实际设施检查，不能只把 `is_land` 当作唯一可达条件。

## 版本、存档与验证

当前生成器版本为 `0.9.0-geo`。同版本、种子、参数可重复生成，跨版本不保证重现旧版世界。导出 JSON 包含完整自然色带、河湖、月度气候、指标与地块；当前页面没有导入旧版世界功能。月份切换只改变展示，不发起世界重生成或推进回合。

Rust 验证覆盖：几何铺满与邻接、参数边界、同种子重放、不同分区密度下自然环境完全一致、平坦高原、雨影方向、水汽账本、无循环汇流、水量守恒、干旱下游来水、湿润凹地成湖与干凹地不成湖。TS 类型检查与浏览器验收覆盖新图层、选择、河湖开关、缩放和导出。

季节验证增加：南北季节反相、海洋调节温差、年均温与年降水回算、雪季储水与回暖融化、永久积雪的储量变化、土壤蓄水跨月使用、缺水和短暖季限制农业，以及整个世界与地块汇总后的水量守恒。

## i18n

新增标签、地理成因、字段说明、图例仍只由中文语言包提供。Rust 返回稳定标识与数据，前端负责 `t(key, params)` 和本地化数值格式。没有新增英文语言包。

## 地质与建设增量（0.6.0-geo）

`environment` 增加 `scale`、`geology_provinces`、`deposits` 与 `sediment_budget`。地块增加 `geology_kind`、地质区组成、矿床份额、`soil_profile` 和 `construction`；边增加 `passage`，不创建道路。地质与建设图层按地块汇总着色。详细单位、土体体积守恒、极小地块回退、廊道限制与阶段收尾建议见 [本轮说明](GEOLOGY_SOIL_CONSTRUCTION.md)。


## 温度与构造增量（0.8.0-geo）

`environment` 增加 `tectonic_regions` 与 `tectonic_boundaries`；地质单元通过 `tectonic_region_id` 关联共同构造背景。温度曲线与潜在蒸散已校准，地形及岩性不再独立生成。所有计算仍在 Rust，前端显示静态构造来源；完整参数、验收与未实现范围见 [温度与构造说明](THERMAL_TECTONIC.md)。

## 海温与地理收尾（0.9.0-geo）

新增 `environment.ocean`、地块 `ocean` 和 `geography`，纯海域改为区域海洋采样平均；陆域和海域气候独立汇总，地块三类面积闭合。自然指纹纳入逐月气候、洋流与地质水分；仍需结合生成器版本，不能作为安全签名。环流边界、海温公式、接口口径与五种子审计见 [收尾说明](OCEAN_GEO_FINISH.md)。自然地理阶段到此冻结，后续由治理玩法验证取舍。
