# 自然地图第二阶段：阴影、共享地表过渡与缩放分级符号

日期：2026-10-23。承接 [第一阶段提案](2026-10-23-natural-map.md)，基线 `67bcf0f`。本阶段只修改表现，不改变世界生成规则。

## 做什么

在已经独立于治理分区的自然海岸内，让高低起伏可读、地形边界不再呈现明显的采样阶梯；放大后才逐步显示森林、山地符号与真实地块编号。经典视图和分析专题保持既有数据口径。

### 地貌阴影

Rust 从原始高程场计算 Horn 3×3 梯度，水平距离按游戏尺度换算为米；固定西北 315° 光照、高度角 45°，环境光与定向光混合。垂直夸张为 24 倍，仅用于可读性，不更改海拔、实际坡度、建设成本或气候。海洋、湖面保持中性，不利用海底高差在岸边画虚假的悬崖。这是地形明暗示意，不是实时太阳或投射阴影。

阴影可独立开关。低海拔平原也可能有起伏；海拔高的平坦高原不会因为高而自动变成陡坡。计算只读取原始环境采样，不消耗随机序列。

### 地表边界

使用共享的非负 cubic B-spline 类别权重，支持范围限于周围四行四列采样，再用四次幂归一化收窄过渡。没有对类别编号做数值平均，也没有分别圆角化各区导致裂缝；这是显示概括，不是重分类。实际海岸和湖泊继续使用第一阶段的路径，不因色彩过渡改变位置或连通性。

由现有 Canvas 2D 一次性生成静态纹理，再作为 SVG image 与原有相机一起变换；没有新 runtime 依赖、WASM、3D 或持续动画循环。原 256×160 采样渲染到 1024×640 纹理，但不声称获得更高精度的地理数据。高倍缩放仍受源分辨率限制。

主图和小地图共用同一缓存纹理。每个世界最多使用深浅主题 × 阴影开关的四种缓存；旧世界由 WeakMap 回收，不在拖动和缩放中重建纹理。缺失第二阶段字段或 Canvas 不可用时退回第一阶段 SVG，自然海岸和地块操作仍可用。

### 地表符号与编号

森林和山地符号来自对应类别的真实环境采样点，经确定性间距筛选；不是逐棵树、山峰坐标测绘或行政区中心的推测。按实际屏幕比例控制可见性，并检查屏幕空间碰撞、视口裁剪与数量上限。地块编号在进一步放大后出现，使用原始 ID + 1，与界面编号一致。

符号可以独立关闭。主图上的编号是治理区标识，不是新建地名；尚无城市、正式国家归属或矿山设施，所以不添加虚构城市、国界、首都、矿山或人口灯光。资源专题仍展示真实地块汇总，不把资源潜力当成矿山位置。

## PR 与上游交付方式

在用户 Fork 中保留两阶段独立审查：Phase 1 → `Develop`，Phase 2 → Phase 1 分支。第二阶段分支自然包含第一阶段，可运行完整效果，但本 PR 的 diff 仅包含本阶段。

通过用户视觉确认后，建议给原仓库一个组合 PR，保留两阶段 commits。不要直接把 Fork 的 `Develop` 全部合并给上游：其中有仅供本地协作的 handoff 文档。应从届时的上游目标分支新建干净分支，只 cherry-pick 本地图升级的提交，再检查冲突并复跑测试。

本次不替用户提前创建或合并上游 PR，也不改写第一阶段已公开的历史。

## 验收与非目标

除新增 `environment.natural_surface.detail` 外，同 seed/config 的 Phase 1 JSON 必须保持完全相同。100/500/2,000 地块的自然表现数据应相同。模式、主题、月份、符号和阴影开关不生成新世界，也不丢失相机、选区或候选地。

检查实际截图而非只看构建成功；保留浅色全图、放大细节、深色和窄屏证据。性能检查关注纹理不在交互时重算、DOM 数量上限和静态缓存；不以此宣称所有设备达到固定帧率。

不加入完整地名系统、政治覆盖、资源设施图标、地貌侵蚀或更高分辨率模拟。效果仍是轻量制图风格，不是最终商业游戏美术。
