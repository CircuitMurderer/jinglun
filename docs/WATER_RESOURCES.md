# 月度河流、地下水与共享水源（0.5.0 引入，当前 0.6.0）

> 0.6.0 增加地质、土层与建设条件，根区容量改由最终土层确定；页面水量可通过游戏尺度元数据换算为百万立方米。下文保留 0.5.0 的水文主体模型，尺度及土壤增量见 [GEOLOGY_SOIL_CONSTRUCTION.md](GEOLOGY_SOIL_CONSTRUCTION.md)。

本轮补齐地理清单中的逐月河流显示、地下水回流、湖底渗漏、天然水质与可规划取水量。自然过程仍由 Rust 在固定 256 × 160 环境网格上计算；TS 只负责选月份、着色、河流线与档案。没有推进游戏月份，也没有实际抽水、用水人口或供水设施。

## 地下水与湖泊交换

每个陆域采样具有一个简化地下水桶。局部地形起伏调节月回流系数（4%—14%）及参考容量（300—1,000 毫米）；它们是游戏参数，不是实测含水层厚度或井深。土壤补给进入桶后，部分水成为当月基流；容量以上的水也排回地表。地下水沿既有无循环汇流网络进入河流、湖泊与出口。

土壤补给的参考年循环用于估计初始地下储量，并显式导出初始水深与矿化度。湖底渗漏在当月河网路由结束后加入地下水，最早下个月才能回流，避免同一份水在一遍汇流中反复经过湖泊。渗漏率为每个湿润采样每月 4 毫米，受湿润面积和实际剩余水量约束。渗入后超过参考容量的水在下月释放，水和盐均不会被截断丢弃。

地下水能够支撑少雨月份的河流，地表水也能渗入地下，是此简化的地理依据；实际交换方向还取决于水位与地质。本版没有地下水水头、侧向含水层网络、达西流、海水入侵或化石地下水。[USGS：地下水与地表水联系](https://pubs.usgs.gov/circ/circ1139/htdocs/natural_processes_of_ground.htm)、[USGS：湖泊与地下水交换条件](https://water.usgs.gov/ogw/pubs/WRI004008/gw2.htm)。

当前湖泊采用向地下渗漏的单向交换近似，地下水回流沿地形网络回到地表；不宣称完整计算所有湖岸的双向交换。原有陆地水桶与额外湖泊蒸发仍为单向耦合，尚未重新求解被淹土壤和湖面能量平衡。

## 天然矿化度与盐分

降水形成的地表产流携带 60 毫克／升的背景矿化度；地下补给采用与地形代理有关的 120—400 毫克／升。这些背景值是游戏简化，不是根据真实岩性做出的化学预测。质量账本以“模型水量 × 浓度”表示溶解物负荷，不把它称为真实千克。

- 河道汇合按水量与溶解物负荷混合。
- 蒸发只移走水；湖泊内的盐保留并浓缩。
- 溢流和渗漏同时带走水及同浓度的盐，渗漏盐进入地下水，再随基流返回。
- 干涸后残盐保留，重新来水时再溶解；不凭空消失。
- 初始湖盐量由参考来水、蒸发与排盐出口估计，单独导出，不模拟历史数千年的盐积累。

模型按矿化度低于 1,000 毫克／升分淡水，低于 10,000 分微咸水，其余归为咸水；空水体／无外排水另行标记。分类只描述盐分，不代表饮用安全、作物适宜性或工业工艺标准。不同用途仍需要设施和具体要求。[USGS：盐度分类背景](https://pubs.usgs.gov/publication/sir20255057/full)、[USGS：溶解物的天然来源](https://water.usgs.gov/nawqa/home_maps/dissolved_solids.html)。

当前没有病原体、重金属、工业污染、泥沙浑浊度、净化和海水淡化设施。淡水资源潜力指数已考虑地下水及关联流域的淡水月份，不再把所有河湖水直接计作淡水；它依旧是潜力而非实际产量。

## 可用水：唯一流域，共享上限

`environment.water_sources` 按最终自然排水出口建立唯一水源，`id` 是出口环境采样编号。它不同于湖盆 `id`。地块通过 `water_source_ids` 引用相同记录，不复制或分配一份独立供水。

每月以最终出口的天然外排水为基础，预留 70% 后，将剩余 30% 记作全流域可规划取水上限。其中只有淡水月份计入 `freshwater_ceiling`；微咸水、咸水不自动转为淡水。70% 是保守、可调整的游戏规则，不是科学通用比例或法规要求。地下水基流已经计入这些出口，不能再加上一份地下水产能。

这是一个排除上游损失、避免重复计算的**规划包络**，还不是已批准、已建设的供水额度。不按当前土地面积预分配，也不能把沿河地块展示的同一流域上限逐块相加。每月所有唯一水源的规划上限之和，等于当月入海及边界外流水量总和的 30%。

无外排的内流盆地保守记为零新增上限，保留其水面、地下水、盐度与生态过程。这不表示工程上绝对无法开发，而是本轮不通过消耗湖泊和地下水参考储量来许诺新增供水。以后水库、取水工程、可接受水位变化与环境目标接入后，再进行实际逐月配水和上下游扣减。关联流域也不代表地块已拥有道路、管线、水权或任意跨流域调水能力。

## 水量与盐分账本

原有陆地账本不变：

```text
陆域降水 = 陆地蒸散 + 土壤补给 + 地表产流 + 积雪储量变化 + 土壤储量变化
```

新增每月约束：

```text
土壤补给 + 湖底渗漏 = 地下水基流 + 地下水储量变化
地表产流 + 地下水基流 = 湖泊额外蒸发 + 湖底渗漏 + 入海流出 + 边界流出 + 湖泊储量变化
地表产流 + 土壤补给 = 湖泊额外蒸发 + 入海流出 + 边界流出 + 湖泊储量变化 + 地下水储量变化
天然溶解物输入 = 出口溶解物输出 + 地下水与湖泊溶解物储量变化
```

湖泊自身满足 `来水 = 蒸发 + 渗漏 + 溢流 + 储量变化`。内部回流、渗漏和盐输送不产生额外外部输入。参考储量和年内净变化均保留；湖泊与地下水耦合后的参考年不强行假装首尾完全一致。

## 接口与界面

- 地块 `groundwater`：初始水深与矿化度；十二个月的土壤补给、湖底补给、基流、月末储水、储量变化与矿化度。地块水深按内部陆域平均，矿化度按储水量加权。
- 湖盆月份增加 `seepage`、`tds_mg_l`、`salt_storage` 和 `quality`；湖盆增加 `initial_salt_storage`。
- 水源月份包括 `natural_outflow`、`ecological_reserve`、`planning_ceiling`、`freshwater_ceiling`、`tds_mg_l` 和 `quality`。自然外排水已经过上游全部湖泊与地下水过程。
- 河段增加 `monthly_flow_index`，由 Rust 用统一的全年平均流量参考尺度计算；不是每个月各自归一化，以免枯水月也被画得很粗。
- “干湿与水系”开放月份选择。底色仍为长期干湿条件，河流线反映指定月份；全年回到年尺度。实际零流量的河段隐藏，保留真实坐标与主支流拓扑。
- SVG 与 Pixi 使用相同强度、线宽和透明度。切月份只重绘，GPU 异步加载期间也保留最新月份，不重建世界或启动持续动画 ticker。
- 地块档案提供地下水逐月表、湖泊盐度与渗漏、共享流域额度与水质表。始终保持一块一色；不叠加湖面色斑。

## 验收

控制测试覆盖：补给延迟与枯季回流、零补给不凭空产水、渗漏不在同月循环、蒸发浓缩与清水稀释、盐随渗漏转移、河湖串联、逐月水量和盐分守恒、共享规划上限总和、所有地块水源引用有效、自然环境独立于治理分区，以及 GPU 异步初始化期间的月份切换和实际断流显示规则。

当前生成器为 0.6.0。同版本和参数仍确定性复现；跨版本不承诺重现旧版水系、淡水潜力和湖泊状态。后续转向建设或地质时不必先补全真实气象、污染和地下水动力学。
