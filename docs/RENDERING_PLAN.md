# 专题地图的高性能动效：PixiJS 与 deck.gl 技术评估

> 日期：2026-10-22\
> 状态：PixiJS 基础接入已落地，使用现有真实河网验证静态 GPU 叠加。物流、能源、迁移与夜间灯光仍待业务数据与后续实现。\
> 用户要求：光点、迁移箭头、夜间灯光、供应链飞线等仅在对应专题视图启用，日常地图不持续展示。

## 1. 结论

可接入，且可以保留 Rust 内核与后端、TS 页面这一架构。两种工具都值得考虑，但不建议首轮同时引入两个 WebGL 渲染系统。

- **针对当前架空二维地图、自由动效与游戏视觉，倾向先验证 PixiJS。** 这是基于项目需求的工程判断，不是已通过性能实测的结论。
- **如果实现时更强调路径、热力、统计与现成分析图层，则优先验证 deck.gl。** 它同样能处理架空平面坐标，不要求先转换为地球经纬度。
- 当前 SVG 原型继续服务地理开发。已固定 PixiJS 8.22.0 并完成真实河网的静态叠加；物流、人口、能源的动态专题仍等实际数据形成后再验证。
- “高性能”需要在目标设备上测量；不能根据库的宣传或示例粒子数量直接保证本项目帧率。

## 2. 官方能力核对

### PixiJS

PixiJS 提供场景组织、精灵与图形绘制。`ParticleContainer` / `Particle` 适合大量轻量点状元素，可区分静态和动态属性；官方目前仍提示粒子 API 可能继续演进，正式接入时需固定版本并检查接口。[粒子文档](https://pixijs.com/8.x/guides/components/scene-objects/particle-container)。

内置滤镜与混合能力可以组合柔光效果；不应假定所有想要的辉光、拖尾都对应一个内置开关。高级滤镜可能来自扩展库，也可能需要另行实现。[滤镜与混合](https://pixijs.com/8.x/guides/components/filters)。

动效由 `Ticker` 或应用自身时钟驱动。`Ticker.stop()` 可以停止相应帧回调；使用共享 ticker 或其他更新源时，也要一并管理。[Ticker 文档](https://pixijs.com/8.x/guides/components/ticker)。

### deck.gl

- `PathLayer`：沿实际坐标序列绘制路径。[文档](https://deck.gl/docs/api-reference/layers/path-layer)。
- `ArcLayer`：连接起终点的弧线，可调高度；它本身不是自动流动的光点系统。[文档](https://deck.gl/docs/api-reference/layers/arc-layer)。
- `TripsLayer`：按路径、逐点时间戳与 `currentTime` 绘制动态轨迹和拖尾。时间值要使用相对时间，避免直接输入大整数 Unix 时间戳造成精度问题。[文档](https://deck.gl/docs/api-reference/geo-layers/trips-layer)。
- `OrthographicView` 与笛卡尔坐标支持非经纬度平面，不需要为了使用 deck.gl 虚构地球坐标。[正交视图](https://deck.gl/docs/api-reference/core/orthographic-view)、[坐标系统](https://deck.gl/docs/developer-guide/coordinate-systems)。

基础弧线、轨迹与数据图层通常不需要自己编写 Shader。特殊的沿弧线追光、复杂箭头、定制辉光或极大规模动态属性，不承诺仅靠配置即可完成。

## 3. 对本项目的比较

下表为结合当前代码与需求的判断。

| 维度 | PixiJS | deck.gl |
| --- | --- | --- |
| 主要组织方式 | 场景对象、精灵、图形、粒子 | 数据集合与图层 |
| 游戏化光点与图标 | 视觉组合自由，适合统一美术风格 | 可用点、图标等图层，但需按图层表达效果 |
| 现成路径与轨迹 | 路线表现与沿路运动需要应用组织 | 有对应的 Path、Arc、Trips 等图层 |
| 架空平面地图 | 与当前 XY 坐标自然对应 | 使用正交视图和笛卡尔坐标也可对应 |
| 与 SVG 叠加 | 共享相机，绘制透明画布 | 共享相机，使用透明覆盖层与受控视图 |
| 后续全面替换地图渲染 | 可逐步整合底图、符号与动效 | 可逐步把多边形、路径与数据覆盖层图层化 |
| 需要自己负责 | 数据含义、轨迹采样、视觉映射、动画管理 | 数据含义、路径时间、图层配置、动画管理 |

当前已有地图、后端接口和 i18n 不会因此全部重写。需要调整的主要是前端渲染适配、相机与专题数据入口。

## 4. 动效与数据的对应

| 专题 | 可用画面 | 应表达的数据 |
| --- | --- | --- |
| 物流 | 沿铁路、公路、航线移动的点或短拖尾 | 实际运输流量、方向、品类与满足情况 |
| 电力 | 电网节点、线路脉冲与区域明暗 | 实际供电、负荷、线路容量与受限状态 |
| 迁移 | 地区间箭头与方向性流动 | 迁出、迁入、双向流量或净流量 |
| 夜间灯光 | 城市与聚落的局部柔光、暗色底图 | 聚居分布、供电与活动强度的综合展示 |
| 国际经济 | 起终点弧线与关系高亮 | 贸易联系、依赖或对外投资 |

### 表现语义

- 运力上限和实际流量分别表达；线路很亮不能同时无解释地表示二者。
- 点的数量或密度可以编码流量，颜色编码类别或负荷；实际数值保留在图例与详情。
- 零流量不继续播放有流量的装饰光点。
- 拥堵、断路、缺电应改变状态，不能只是更热闹地发光。
- 电力脉冲是方向与负荷的示意，不模拟电磁传播速度。
- 人口迁移可以用汇总符号，不逐个居民生成一个动画实体。
- 夜间灯光初期如只基于地区汇总数据，需采用示意范围，不能假装已经掌握实际街区和建筑分布。
- 双向流量与净迁移需要可区分，不能仅用一根箭头隐去另一方向。

### 实际路径与关系飞线

物流模式的动点应沿 Rust 计算出的真实路线运行。世界经济关系模式可以采用起终点弧线展示联系，但需明确它不等于货物实际跨越山海的路径。

如果使用 `ArcLayer`，不能把视觉弧线当成模拟引擎中新建的运输通道。选择一条联系后，可以再展开其真实通道与瓶颈。

## 5. Rust 与 TS 的边界

### Rust 计算

运输分配、通行、路线、容量、损耗、到货、供电、人口迁移、经济与月度状态。需要重采样或大量聚合的专题数据也由 Rust 产生或缓存。

### TS / 浏览器 GPU 展示

相机、绘制、颜色、透明度、符号大小、选中高亮与视觉时间插值。沿给定路线移动一个光点属于页面动画，不在 TS 重新计算货物、人口或经济结果。

显示时钟与游戏时钟独立：玩家可以暂停、减弱或关闭动画，世界状态不变；重复播放已结算月份不再次消费资源，不迁移第二遍人口。

后端按回合或相关状态变化提供专题快照，前端用同一份快照连续展示。无需每一帧向 Rust 发请求，也无需为此直接引入每帧 WebSocket 推送。

## 6. 未来专题数据契约

保持渲染库无关，建议预留以下信息；本轮不创建实际类型或接口。

| 数据 | 内容 |
| --- | --- |
| 快照标识 | 世界 ID、地图版本、回合、数据修订与数据口径 |
| 网络节点 | 稳定节点 ID、世界坐标、角色 |
| 网络线路 | 稳定线路 ID、两端、模式、路径坐标、几何版本 |
| 运输流量 | 来源、目标、实际路线、货物、单位、数量、方向与满足率 |
| 能源状态 | 供需、输送负荷、有效能力、供电率、断线或受限原因 |
| 迁移记录 | 来源、目标、人数、时间口径、双向量与原因 |
| 表现用路径 | 累计距离或相对时间、段序号、方向，便于前端插值 |

静态路线与每月流量分开传输。路线未变时只更新指标，不重发和重建全图几何。

单位与时间口径必须明确。动画周期压缩一个月的展示，不自动等同于真实旅行时间；实际在途和到货仍由 Rust 判断。

## 7. 接入现有 SVG 的路径

初期可以保留 SVG 底图，在同一画布容器叠加一个透明 WebGL 画布，仅画专题符号与动效。

届时需要先把当前 `MapView` 私有的平移、缩放与选择职责抽为共享视图状态，统一提供相机中心或变换、视口大小、缩放与选中对象。具体接口服从实现，不为未来所有渲染器提前建设复杂框架。

必须处理：

- SVG 的留白、适应画布、平移与 GPU 坐标一致。
- 窗口缩放、像素比变化和窄屏布局下都保持对齐。
- 统一手势入口，避免两个画布各自拖动而相互抢事件。
- 装饰点不拦截地块点击；需要选中的路线单独参与命中。
- 浮层、图例与表格继续走中文 i18n，不在粒子逻辑里硬编码文案。

deck.gl 的透明覆盖、受控视图可用于此类同步。[Deck 文档](https://deck.gl/docs/api-reference/core/deck)。但“可以叠加”不等于现有 SVG 私有变换无需适配。

当底图规模、图层数量或交互同步成本真正成为问题时，再比较统一 GPU 地图与继续混合渲染的成本。不会因为未来想画光点，就立即重写目前几百个多边形。

## 8. 只在相关界面启用

1. 普通地理、建设等界面使用平静底图，默认不播放流量动效。
2. 首次进入物流、能源、迁移或夜间专题时，按需加载相应渲染模块并读取快照。
3. 动态模块就绪后启动展示时钟，允许改变物资、方向或地区筛选。
4. 切走时停止动画、停止不必要的数据刷新、取消过期请求；保留适量可复用几何缓存。
5. 标签页不可见、画面不可见或用户选择减少动态效果时，暂停或降为静态表示。
6. 长期不用、重开世界或销毁页面时释放旧纹理、图层、监听与 GPU 资源。

不能仅设置 CSS 隐藏并让动画继续运行。对 deck.gl 隐藏图层可以使用 `visible`，但应用仍须停止外部动画更新；不需要的命中检测保持关闭。[deck.gl 性能文档](https://deck.gl/docs/developer-guide/performance)。

## 9. 性能验证与降级

正式接入时使用相同快照比较：只有底图、静态网络、动画网络三个状态；分别测量不同路线与粒子规模，以及普通与高像素比屏幕。既记录帧率，也记录界面延迟、CPU、显存与切换后残留活动。

优化方向：静态几何缓存、对象复用、按缩放聚合、限制屏幕粒子数量、关闭装饰命中、避免逐点滤镜和不必要全屏后处理。频繁更换数据可能导致重建 GPU 缓冲；滤镜也有额外开销。[deck.gl 性能](https://deck.gl/docs/developer-guide/performance)、[PixiJS 性能建议](https://pixijs.com/8.x/guides/concepts/performance-tips)。

GPU 不可用、上下文丢失或设备较慢时，降级为静态路线、箭头、颜色与数值；专题仍应可用，不影响 Rust 模拟。精确数值和图例始终可查看，不把重要信息只编码在动画速度中。

## 10. 当前决定

- 接纳“专题视图才启用 GPU 动效”的产品方向。
- 在本次技术接入授权下固定安装 PixiJS 8.22.0，保留 SVG 底图，只以现有河网进行静态图层验证；deck.gl 暂不引入。
- 当前不创建光点演示或构造虚假业务流量，不把 `flow_index` 当作实际流速。
- 业务系统形成真实数据后再制作相应动态专题。
- 后续地理设计继续沿用渲染库无关的世界数据，避免绑定到 SVG、PixiJS 或 deck.gl 的对象类型。

## 11. 已落地的基础接入

- `map-camera.ts` 保存世界尺寸、视口、像素比、平移、缩放与选中 ID。SVG 的 `xMidYMid meet` 留白与 GPU 的投影由同一份状态确定，手势仍只由底图接收。
- `river-overlay.ts` 仅在开启河流线时动态导入 GPU 模块。初始化串行化，关闭或重开世界会让旧请求过期，迟到的渲染器立即销毁；模块失败与上下文丢失均回到可用的 SVG 河网。
- `pixi-rivers.ts` 使用透明 WebGL 画布和真实河网，按陆域地块遮罩裁剪，线宽与 SVG 一样保持屏幕可读性。选择与中心点位于上层 SVG，画布不拦截地块点击。
- `river-display.ts` 为 SVG 与 GPU 提供相同的主要河网子集。按汇流拓扑修剪不足三个环境采样间距的细短侧支和孤立水系，保留每个主要水系的主干及其短连接，不修改任何保留路径坐标或原始世界数据，避免细短网格河段放大后成为一排横杠。
- 不创建 ticker，也不启动动画循环；仅在相机、视口或可见性变化时重绘。标签页隐藏或画面离屏时不绘制，关闭图层和销毁页面时释放场景、监听器、观察器与 GPU 资源。
- 监听容器尺寸与设备像素比变化；GPU 绘制像素比上限为 2。使用 `ResizeObserver` 与分辨率媒体查询处理窄屏与跨屏调整。

验证范围：前端 13 项自动测试覆盖坐标留白、缩放锚点、相机边界、异步关闭、重开世界、模块失败、上下文丢失回调与销毁，以及截图中的短横杠回归、短主干连接保留和长横向河流保留。Rust 12 项测试验证世界生成、季节水分和接口。类型检查及生产构建通过，PixiJS 被拆到按需加载的独立模块。

浏览器实测覆盖 800 与 2,000 地块、普通视图不创建画布、2 倍像素比桌面、390 像素窄屏、缩放平移、点击选择、关闭图层与重新生成世界。开发验收页 `frontend/tests/rendering.html` 使用真实接口生成地图，可通过按钮触发 `WEBGL_lose_context`；已验证自动切回 SVG、重新开启后回到 GPU，以及销毁重建后仅保留一张画布。

这轮验证证明基础叠加与生命周期可用，不代表已经完成动态网络或粒子性能测试。尚未测量未来专题的帧率、CPU 与显存；业务快照、动画时钟、减少动态效果开关和大规模流量性能验收留待实际动态专题实现。

### 月度河流（0.5.0-geo）

已接入 Rust 的月度河段强度，SVG 与 WebGL 共用同一线宽、透明度和断流隐藏规则；同一全年参考尺度保证丰枯可以直接比较。切换月份仅重绘，不启动 ticker。GPU 加载完成时同步最新月份，关闭重开及 SVG 降级沿用同一时期。水文来源和守恒见 [WATER_RESOURCES.md](WATER_RESOURCES.md)。
